Act as the materials-planning engineer picking up after a failed ERP rollout. It truncated the authoritative inventory positions at `/app/data/inventory_positions.json` and left the requirements planner at `/app/workflow/plan_requirements.go` running against draft rules the planning board later reversed. Nothing the planner emits can be trusted until those positions are rebuilt. A pre-rollout snapshot and a journal of the movements posted after it survive beside the truncated file under `/app/data`. How the two combine, what a retraction does, which fields survive and the order of the result are governance decisions, and the positions must be restored at their expected path first.

Then restore the planner, a Go program built with the toolchain installed here and staying a single `package main`. Preserve its `--input` and `--output-dir` options and their defaults; the item master, bill of materials, independent demand, planning calendar and planning policy are always read from their fixed absolute paths under `/app/data`, and `--input` selects the positions file only. `/app/docs/report_spec.json` is the output contract: paths, schemas, required-field lists, container shapes and sort orders. It says nothing about how any value is derived. Reconstruct that from `/app/incident/planning_governance_log.md`, mostly routine minutes, where the later dated decision governs. A run writes exactly `/app/output/summary.json`, `/app/output/item_plan.json` and `/app/output/exception_queue.jsonl` inside the contract's 90-second budget. Derive every value from the operational inputs: standard library only, no planning or solver library, correct against an alternate positions file, identical across reruns, and leave the frozen rollout snapshot in `/app/workflow` untouched.

Both stages are graded on their outcomes. The rebuilt positions at `/app/data/inventory_positions.json` are compared against the governed replay and must carry only the declared record fields, ascending by item id, with none of the journal's own bookkeeping surviving; several plausible misreadings of that replay are each required to differ from it, and a run that leaves the step undone cannot match the reference. The restored planner is then compared field for field and digest for digest against a reference run, both on the shipped positions and on an alternate positions file held back from this environment, so a result reverse-engineered from what is here will not carry. Every dated decision the log settles is additionally checked on its own crafted instance -- how an item's low-level code is fixed, how the lead-time offset is counted, what a shortfall is measured against, when dependent demand lands on a component, how each lot policy sizes an order, how a yield changes what is released against what arrives, what a line's scrap allowance adds, how a phantom assembly is passed through, which bill-of-materials line is effective, and what the firm fence does to a release -- so each rule has to be right on its own and not merely on average. Alongside those: the summary's every total must agree with the artifacts emitted beside it; the output directory must hold the three contracted files and nothing else; two runs over the same input must be identical and the no-argument run must match an explicit one; every input the contract fixes to an absolute path must actually influence the output; the frozen snapshot must be unmodified; and the graded run must finish inside the published budget. The standard-library requirement is read from the planner's Go import declarations alone -- how you build a path or name a file is your own choice.
